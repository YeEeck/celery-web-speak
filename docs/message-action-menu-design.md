# 消息操作菜单设计

## 背景

文字频道的消息删除目前依赖消息行上始终可见（桌面端 hover 显示）的垃圾桶按钮，仅服务器管理员可见。该按钮占据消息行空间、对移动端几乎不可用（触屏无可靠 hover），且管理员之外的用户没有任何消息操作入口。

项目已有服务器、频道和语音参与者三类应用内右键菜单，以及全局右键菜单抑制策略。消息行应沿用同一模式，以右键菜单承载消息级操作。

## 设计决策

- 消息行（头像与正文整体）成为应用内右键菜单触发区域。桌面鼠标右键在指针位置打开菜单；触屏长按打开同一菜单。
- 所有服务器成员均可打开消息菜单，不限于管理员。
- 菜单提供"复制文本"，始终复制整条消息的完整正文，不感知选区。选中文本片段的复制继续使用桌面端原生选区与 Ctrl+C。
- 消息行成为自定义菜单触发区域后，按全局右键菜单策略的既有规则，消息正文上的文本选区不再触发浏览器原生菜单例外。桌面端的文本选择能力本身不受影响。
- "删除消息"仅对有权删除该消息的用户显示：服务器所有者和服务器管理员可删除任意消息；消息作者可删除自己发送的消息。平台管理员不凭平台角色获得删除权，必须同时持有当前服务器的所有者或管理员角色。
- 删除单击直接执行，不弹出二次确认。消息从界面消失即为成功反馈；请求失败时显示服务端返回的错误。
- 消息菜单不提供键盘入口。消息行不进入 Tab 序，保持键盘用户快速到达消息编辑器的路径。
- 菜单不承载编辑、引用、转发或反应等操作；当前产品不存在这些能力，菜单结构为未来扩展预留位置但不预置禁用项。

## 权限模型

| 操作者 | 目标：自己的消息 | 目标：他人的消息 |
| --- | --- | --- |
| 普通成员 | 允许 | 禁止 |
| 服务器管理员 | 允许 | 允许 |
| 服务器所有者 | 允许 | 允许 |
| 平台管理员（无本服务器角色） | 禁止（非成员时无法访问频道） | 禁止 |

服务端是最终授权边界：路由中间件仅要求服务器成员身份，删除权限在业务逻辑层按"作者或管理员"校验。前端按同一规则决定"删除消息"的显隐，鉴权失败时以服务端结果为准。

已退出服务器的成员无法访问频道，自然不能删除任何消息，即使消息仍然存在于频道中。

## 菜单结构

菜单为纯命令列表，不包含头部（消息行已展示作者头像与名称）：

1. 复制文本。
2. 分隔线与"删除消息"，仅在操作者有权删除该消息时显示；该项使用危险样式。

菜单使用 `role="menu"` 语义，支持方向键、`Home`、`End`、`Escape` 在菜单项间导航，与频道菜单的键盘行为一致。

## 交互与反馈

- 桌面鼠标右键在指针位置打开菜单并阻止浏览器默认菜单；触屏长按在触摸位置打开同一菜单，并取代该行的原生长按选字行为。
- 菜单位置限制在视口范围内，不被窗口边缘裁切。
- 同一时间最多打开一个消息菜单；再次右键其他消息时替换当前菜单。消息菜单与服务器、频道、语音参与者菜单互斥，由 AppShell 统一协调。
- 点击菜单外、按 `Escape`、滚动消息列表或调整窗口尺寸时关闭菜单。
- 切换频道、切换服务器或目标消息从列表消失时关闭菜单。
- "复制文本"完成后关闭菜单，复用全局反馈区域显示"文本已复制"或"复制失败，请重试"。
- "删除消息"单击后关闭菜单并发起请求；请求期间不阻塞其他操作。成功时消息经现有 WebSocket 广播从所有客户端移除；失败时显示服务端错误信息。
- 打开菜单不改变当前频道、不触发已读状态变化、不影响语音连接。

## 服务端边界

- 消息删除路由的中间件从服务器管理员要求降级为服务器成员要求。
- 业务逻辑层在执行删除前校验：操作者是消息作者，或操作者在当前服务器持有所有者/管理员角色；两者均不满足时拒绝并返回权限错误。
- 审计日志保持现有结构，记录操作者、服务器与消息标识；作者删除自己的消息同样写入审计。
- 删除成功后继续通过现有 `message_deleted` 广播通知服务器内所有连接。

## 前端边界

- 新增独立的 `MessageActionMenu` 组件，通过 Teleport 渲染到页面顶层，沿用现有菜单的视口约束与关闭行为。
- 菜单状态由 AppShell 统一持有，负责与其他全局菜单的互斥和删除请求的执行。
- ChatPane 移除消息行上的垃圾桶按钮及其样式，改为在消息行上发出菜单打开请求（右键与长按）。
- "删除消息"的显隐由 AppShell 根据当前用户角色与消息作者计算。
- 触屏长按通过消息行上的 `contextmenu` 事件接管，不依赖视口宽度或设备名称判断输入来源。

## 验收标准

1. 桌面端右键任意消息行（头像或正文）在指针位置打开应用内菜单，浏览器默认菜单不出现。
2. 触屏长按消息行在触摸位置打开同一菜单，不触发原生选字浮层。
3. 所有成员均看到"复制文本"；复制结果为整条消息正文，反馈提示约两秒。
4. 普通成员对他人的消息看不到"删除消息"；对自己发送的消息可见并可成功删除。
5. 服务器管理员和所有者对任意消息可见"删除消息"并可成功删除；删除后所有客户端的消息列表同步移除该消息。
6. 无权限的删除请求被服务端拒绝，前端显示错误提示。
7. 消息行上的文本选区右键不再弹出浏览器菜单，桌面端拖选与 Ctrl+C 不受影响。
8. 菜单与服务器、频道、语音参与者菜单互斥；滚动、Escape、外部点击、切换频道或服务器时正确关闭。
9. 菜单在视口边缘保持完整可见，键盘方向键导航行为与频道菜单一致。
10. 桌面与移动视口不存在遮挡、溢出或文字截断。

实现完成后运行 Go 全量测试、前端类型检查、生产构建和相关 Playwright 场景，并使用桌面与移动视口验证实际布局。

## 文档归属

本设计调整的是可局部替换的 WebUI 交互与消息删除鉴权细节，不形成难以逆转的架构锁定，因此不创建 ADR。全局右键菜单策略文档同步更新消息行触发区域与触屏长按的说明。产品领域术语无新增，`CONTEXT.md` 不变。
