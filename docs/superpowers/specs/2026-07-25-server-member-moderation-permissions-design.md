# 服务器成员审核权限提示修复设计

## 背景

服务器管理员在管理面板中选择服务器所有者时，页面会显示“服务器管理员不能管理其他管理员。”；选择真正的服务器管理员时，页面却会显示禁言、封禁和移出服务器等审核操作。

现有产品规则已经明确：服务器管理员只能审核普通成员，不能审核服务器所有者或其他服务器管理员。服务端的成员审核接口也已经执行这一限制。本次问题来自前端可用性判断与提示文案不一致。

## 目标

- 让成员详情中的审核操作严格遵循现有服务器角色层级。
- 针对服务器所有者和其他服务器管理员显示不同的不可管理原因。
- 为平台管理员选择服务器所有者的场景提供准确的所有权转让指引。
- 保持成员列表完整，使无权管理的角色仍可见、可选并可查看基本身份信息。

## 非目标

- 不改变服务器角色模型或服务端授权规则。
- 不改变成员管理面板布局。
- 不改变成员添加、角色任命、所有权转让或平台账号管理流程。
- 不隐藏或禁用成员列表中的服务器所有者和管理员条目。

## 权限矩阵

“允许审核”表示可以执行语音禁言、文字禁言、临时封禁、永久封禁、解除封禁和移出服务器。

| 操作者 | 目标：普通成员 | 目标：服务器管理员 | 目标：服务器所有者 |
| --- | --- | --- | --- |
| 服务器管理员 | 允许审核 | 禁止审核 | 禁止审核 |
| 服务器所有者 | 允许审核 | 允许审核 | 不适用，当前用户不出现在可选列表中 |
| 平台管理员 | 允许审核 | 允许审核 | 禁止审核 |

角色修改继续遵循现有规则：服务器所有者和平台管理员可以任命或撤销服务器管理员；服务器管理员不能修改成员角色；服务器所有者不能在成员管理中被改为其他角色。

## 前端行为

成员管理面板在选中成员后，根据当前操作者权限和目标服务器角色生成统一的审核权限结果。该结果同时决定审核控件是否显示，以及禁止审核时显示的原因，避免两套条件再次产生偏差。

允许审核时，显示现有审核控件，不显示权限提示。禁止审核时，隐藏全部审核控件，并按场景显示以下文案：

| 场景 | 提示文案 |
| --- | --- |
| 服务器管理员选择其他服务器管理员 | 服务器管理员不能管理其他管理员。 |
| 服务器管理员选择服务器所有者 | 服务器管理员不能管理服务器所有者。 |
| 平台管理员选择服务器所有者 | 服务器所有者不能在成员管理中被审核；如需更换所有者，请使用所有权转让。 |

所有成员继续在列表中可见并可选。禁止审核时仍显示目标成员的头像、显示名称、登录名和服务器角色，不显示禁言、封禁、移出服务器等操作。

## 实现边界

改动限定在管理面板内部。使用一个小型权限结果计算统一表达 `allowed` 与 `reason`，模板只消费这一结果。无需新增全局权限模块，也无需扩展成员 DTO 或调用额外接口。

服务端已有 `guildCanManageTarget` 作为最终授权边界：服务器管理员不能审核管理员或所有者，服务器所有者和平台管理员可以审核管理员，所有者始终不能通过成员审核接口被操作。因此本次不修改后端行为。

## 错误与状态处理

- 前端隐藏操作只是交互约束，不能替代服务端鉴权。
- 成员角色因实时事件或重新加载而变化时，权限结果随响应式数据立即重新计算。
- 若请求发起后权限发生变化，沿用现有请求错误展示，由服务端拒绝越权操作。
- 不可管理提示与审核控件互斥，避免同时展示禁止说明和可执行按钮。

## 测试与验收

补充针对成员管理面板的 Playwright 回归覆盖：

1. 服务器管理员选择普通成员时，审核控件可见且不显示权限提示。
2. 服务器管理员选择其他管理员时，全部审核控件隐藏，并显示“服务器管理员不能管理其他管理员。”
3. 服务器管理员选择服务器所有者时，全部审核控件隐藏，并显示“服务器管理员不能管理服务器所有者。”
4. 服务器所有者选择管理员时，审核控件保持可用。
5. 平台管理员选择服务器所有者时，审核控件隐藏，并显示所有权转让指引。
6. 所有不可管理的目标仍保留在成员列表中且可以选中。

实现完成后运行：

- 前端类型检查。
- 前端生产构建。
- 相关 Playwright 用例。
- Go 全量测试，确认服务端权限行为没有回归。

## 验收标准

- 服务器管理员只能看到普通成员的审核操作。
- 所有者、管理员和平台管理员场景均显示与操作者及目标角色一致的提示。
- 角色修改能力与现有产品规则保持不变。
- 服务端接口和数据模型没有变化。
- 自动化测试覆盖权限矩阵中的关键允许与禁止路径。
