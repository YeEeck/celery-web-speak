# 静音说话提醒设计

## 背景

用户可能保留此前设置的麦克风静音状态，并在已经加入语音后忘记当前声音不会发送。本设计需要在用户尝试说话时及时提示静音状态。

## 已确认边界

- 仅在用户已经加入语音时检测，未加入语音时不检测。
- 麦克风声音不向语音频道发布，也不录制检测到的音频。
- 为判断用户是否正在说话，静音期间允许应用继续在本地采集并分析麦克风输入。
- 静音说话提醒复用现有的页面级麦克风授权流程，不在加入语音或 VAD 初始化时额外请求权限。若页面初始化时未获得麦克风权限，本次语音会话不提供该提醒。
- 已有授权时，为 VAD 取得或保留本地麦克风流不属于再次请求权限，但浏览器可继续显示麦克风正在使用的系统指示。
- 用户离开语音后立即停止用于检测的麦克风采集。
- 仅当用户主动关闭麦克风时触发提醒。
- 耳机静音连带关闭麦克风时不触发提醒；此时用户无法听到频道声音，不容易形成自己仍在正常通话的错觉。
- 服务器管理员禁言时不触发提醒；该状态继续由现有管理员禁言反馈表达。
- 提醒必须在应用窗口失焦、被其他窗口遮挡或最小化时仍可被用户感知。
- 视觉反馈只能作为辅助，不能作为静音说话提醒的唯一或主要反馈。
- 静音说话提醒以短促、可辨识的专属提示音作为主反馈，通过用户当前选择的输出设备播放。
- 该提示音为专属固定双音，不归入操作提示音，不接受系统预置音效选择或自定义音效上传；决策记录见 [ADR-0006](./adr/0006-muted-speaking-reminder-not-customizable.md)。
- 每次提醒事件触发时，同步让麦克风静音按钮高亮 3 秒，并在窗口可见时显示“你正在静音时说话”的 tooltip。即使用户仍在持续说话也不延长显示；辅助视觉反馈与提示音共用触发和冷却，不额外弹出 Toast 或系统通知。
- 系统通知不作为主反馈，避免依赖额外通知权限；语音播报不作为主反馈，避免过度打断通话。
- 在“用户设置 → 音频 → 输入”提供独立的“静音时说话提醒”开关，默认开启。
- 该开关只保存在当前浏览器的 `localStorage`，不写入账号资料，不跨浏览器或设备同步。
- 不向用户提供 VAD 模式或检测灵敏度设置，调优通过版本更新完成。
- 关闭开关后停止为本功能进行的本地说话检测，并且不再播放提醒；不要求用户关闭其他应用提示音。

## 提醒节奏

- 用户主动静音或以主动静音状态加入语音后等待 1 秒再开始判定，避免把静音操作前的尾音算作忘记静音。
- 只在语音连接状态为 `connected` 时运行检测。正在连接或断线重连时停止 VAD 并清空当前说话判定；恢复连接后若仍满足触发条件，重新等待 1 秒再判定。
- 连续检测到约 600 毫秒的说话活动后播放一次提示音。
- 同一段持续说话只提醒一次，不按固定周期重复。
- 连续安静至少 1.5 秒后才重新等待下一段说话。
- 相邻两次提示音至少间隔 10 秒；即使期间出现多段说话，也不突破该冷却时间。
- 解除主动静音、离开语音或关闭提醒开关时立即取消当前判定和冷却状态。

## 提示音设置

- 独立的“静音时说话提醒”开关决定是否启用本功能。
- 静音说话提醒使用固定的专属双音提示，不复用加入、退出或消息音色，不提供单独的音色选择器。
- 提示音遵守现有应用提示音总开关和提示音音量，并跟随首选输出设备。
- 加入、退出和消息三个提示音分类开关不影响静音说话提醒。
- 当应用提示音总开关关闭或提示音音量为 0 时，不播放静音说话提醒，并停止为本功能运行 VAD。重新开启提示音或调高音量后，若用户仍处于主动静音状态，则重新启动检测。
- 提醒事件触发后，如果输出设备切换或 Web Audio 播放失败，仍显示辅助视觉反馈并记录诊断日志；不改用 Toast 或系统通知。

## 平台范围

- 桌面 Chrome、Edge 和 Electron 必须在窗口失焦、被其他窗口遮挡或最小化时仍可靠检测并播放提醒。
- Android Chrome 在页面位于前台时支持；进入后台后受浏览器和系统生命周期限制，只尽力执行，不承诺可靠。
- Android 原生语音端后续由原生语音服务实现同一触发范围、提醒节奏与设置语义，不依赖后台 WebView、Web Audio 或 Web 定时器。

## 说话检测

- 使用纯本地的 WebRTC VAD（`libfvad` WebAssembly）判断用户是否正在说话，不以固定音量阈值直接触发提醒。
- `libfvad` 的 WebAssembly 和运行资源随应用部署，检测音频和结果均不上传。
- 服务端 CSP 通过 `script-src 'self' 'wasm-unsafe-eval'` 允许同源 VAD Worker 编译 WebAssembly，但不开放普通 `'unsafe-eval'`；发布验收需确认响应头允许 WASM 编译。
- 本功能不引入 Silero VAD、ONNX Runtime 或其他神经网络推理运行时。静音说话提醒只是可关闭的状态提示，轻量 VAD 配合连续说话确认、重新武装和冷却即可控制可感知的误报，不值得为更高分类精度承担数 MB 的模型与运行时成本。
- 检测策略优先控制误报，允许轻声、距离较远或过短的说话偶尔漏报；首版使用 `libfvad` 最不灵敏的 `VERY_AGGRESSIVE`（模式 3），若实际测量显示正常说话频繁漏报，再通过版本更新调整为模式 2。
- 人工场景验收发现首版模式 3 对正常说话频繁漏报，已通过版本更新回退至 `AGGRESSIVE`（模式 2），在延续误报优先策略的同时放开对正常说话的检出。
- VAD 专用的本地采集固定开启浏览器回声消除和降噪，关闭自动增益控制；这些设置不跟随用户为实际发送音频选择的处理开关，也不会改变解除静音后的发送链路。
- VAD 只产生静音说话提醒所需的本地状态，不参与麦克风门控，不改变 DTX、音轨发布或发送音频。
- 关闭提醒、解除主动静音或离开语音时停止 VAD，避免没有用户可见收益的持续计算。
- `libfvad` 资源加载、实例化或运行失败时，停用当前语音会话的静音说话提醒并记录诊断日志；不回退到 RMS 音量阈值，不弹出错误提示，不影响语音连接和静音状态。
- 本阶段新增的 VAD 与现有 `MicrophoneActivityMonitor` 隔离，只分析本地用户在主动静音期间的输入。
- 现有成员说话高亮继续使用既有音量阈值，不对远端成员运行 VAD，也不在本阶段改变高亮语义。
- 后续可以评估复用 VAD，但必须另行验证成员高亮行为、远端音轨数量下的性能和资源生命周期。

## 资源预算

- 生产构建中由本功能新增的 `libfvad` WebAssembly、JavaScript 封装和其他相关资源合计不得超过 100 KB gzip。
- 如果超过包体预算，暂停实现并重新评估依赖与封装方案，不直接放宽上限。
- 本阶段不为 CPU 占用设定硬性验收上限，以 Release 构建的实际测量结果评估是否值得上线及是否需要调优。

## 验收策略

- 不为 VAD 建立量化的误报率、漏报率、精确率或召回率 SLA，不为本功能建设专用语料评测体系。
- 人工场景验收覆盖正常说话、轻声、键盘、风扇、扬声器播放他人语音和背景音乐，记录 Release 构建在实际设备上的表现。
- 自动测试重点验证连续说话判定、重新武装、冷却、连接状态和各种停止条件，不对 `libfvad` 的声音分类结果做伪精确的端到端断言。
