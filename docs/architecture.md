# Celery Web Speak 技术架构

> 当前实现基线：单部署受控多服务器。系统仍面向单机、单 Go 进程和单 LiveKit 节点部署，不具备水平扩展的一致性设计。

## 总体结构

```text
Browser (Vue 3)
  | HTTPS: 页面与 /api/*       | WSS: /api/ws
  v                            v
Caddy Gateway (可选) --------> Go Application ------> SQLite (/data/celery.db)
  |                              |
  | WSS: /rtc, /rtc/*            | HTTP: RoomService API
  v                              v
LiveKit Server <----------- internal Docker network
  ^
  | WebRTC: 7882/UDP, 7881/TCP
Browser
```

默认启用 Caddy Gateway（`caddy:2.11`，通过 Compose profiles 可选禁用），终止 HTTPS 并将 `/rtc`、`/rtc/*` 转发至 LiveKit，其余 HTTP 与业务 WebSocket 请求转发至 Go 应用。Gateway 使用 Let's Encrypt `shortlived` profile 自动签发和续期公网 IP 证书；`default_sni` 使不发送 SNI 的裸 IP 浏览器连接也能选中证书，显式 HTTP 路由确保非标准 `HTTPS_PORT` 的重定向保留端口。禁用 Gateway 时需部署方自行提供 HTTPS 反代（参考 `deploy/nginx.conf.example`）。WebRTC 媒体不经过 Go 或 Gateway，而是由浏览器直接连接 LiveKit 暴露的 UDP 或 ICE/TCP 媒体端口。

Go 应用提供嵌入式前端、认证与管理 API、文字聊天 WebSocket、LiveKit 访问令牌、Webhook 和房间管理。SQLite 保存频道、消息、已读位置及账号数据；在线状态、发送限流、WebSocket 客户端集合和语音房间占用快照保存在 Go 进程内存中，LiveKit 保存实际媒体房间状态。

## 技术组件

- 前端：Vue 3、TypeScript、Vite、Pinia、Lucide、TanStack Virtual、LiveKit Client SDK；当前没有引入 Vue Router。
- 后端：Go 1.26、标准 `net/http`、Gorilla WebSocket、LiveKit Server SDK。
- 数据库：`modernc.org/sqlite` pure Go 驱动；构建时使用 `CGO_ENABLED=0`。
- 密码：bcrypt 默认成本哈希，不保存明文密码。
- 会话与邀请码：随机不透明令牌；匹配时使用 SHA-256 哈希。新邀请码额外保存仅平台管理员可读取的原码，旧记录不补造原码。
- 部署：Go 应用镜像、LiveKit 官方镜像、Caddy Gateway（可选）和持久卷组成 Docker Compose；默认通过 Gateway 自动管理 HTTPS 证书，也可禁用后由部署方自行管理反代与证书。

## 前端结构

前端没有多页面路由，登录态决定根组件显示认证界面或主应用界面。三个 Pinia Store 分担主要状态：

- `app`：全局账号与服务器摘要、当前服务器上下文、分频道消息分页/草稿/滚动/未读状态、当前服务器成员、在线账号及客户端类型和业务 WebSocket；断线后每 2.5 秒尝试重连。
- `voice`：当前连接的服务器与语音频道摘要、当前服务器语音房间快照、LiveKit Room、音频设备、联动的麦克风/耳机静音状态、参与者状态和本地音量；浏览其他服务器不会断开现有语音。
- `sounds`：加入、退出和新消息提示音开关、音量、来源选择（系统预置或自定义音效）、输出设备与 300ms 同类限流；自己的主动退出可绕过限流，但仍遵守开关、音量和耳机静音状态；自定义音效的原始音频数据保存在浏览器 IndexedDB。

文字列表使用 TanStack Virtual 只渲染视口附近的不等高消息。每个文字频道的历史记录以消息 ID 为游标每页读取 50 条，加载后修正该频道滚动位置；前端内存分别按各频道消息保留数量裁剪。最后已读消息由服务端同步，草稿和滚动位置按频道保存在 `localStorage`。

音频处理分为三层：

- 本地麦克风采集明确请求关闭浏览器自动增益，音轨通过自定义 LiveKit Track Processor 接入 Web Audio GainNode，实现固定的 0%-300% 麦克风增益。
- 远端用户的麦克风音量和背景音音量按音轨来源独立保存并应用；各自与全局扬声器音量在客户端相乘，分别限制在 0%-300%，再通过 LiveKit 参与者音量接口应用。
- 操作提示音的两类来源：系统预置音效由 Web Audio Oscillator/GainNode 本地合成；自定义音效为用户上传的音频文件，经 `decodeAudioData` 解码为 `AudioBuffer` 后由 `AudioBufferSourceNode` 播放。两者优先通过 `setSinkId` 路由到所选输出设备，不支持时使用系统默认设备。

麦克风增益、扬声器音量、按用户麦克风音量、按用户背景音音量、提示音开关/音量/来源选择保存在浏览器 `localStorage`；用户上传的自定义音效原始音频文件保存在浏览器 IndexedDB（`cws.sounds` 数据库的 `customSounds` 对象存储，按事件独占一条记录）。账号资料、权限、禁言与频道设置由服务端持久化，不在不同浏览器间同步本地音频偏好。

## HTTP 与实时接口

Go 使用 `http.ServeMux` 的方法路由，接口按职责分组：

- 公开接口：健康检查、登录、邀请码注册。
- 全局接口：退出、个人资料、平台 Bootstrap、业务 WebSocket、平台账号和邀请码。
- 平台管理员接口：服务器创建、重命名、元数据列表、显式加入、所有权转让和删除，以及全局账号、角色和邀请码管理。
- 服务器作用域接口：服务器 Bootstrap、成员与角色管理、禁言/封禁、频道、消息、已读和语音 Token。

`GET /api/bootstrap` 只返回全局账号和可见服务器摘要。`GET /api/servers/{serverID}/bootstrap` 在验证成员关系后返回当前服务器的成员、频道、已读、在线和语音快照。当前文字频道的最新 50 条消息通过服务器作用域消息接口加载。

业务 WebSocket 广播在线状态、频道创建/更新/删除、消息创建/删除、语音房间快照、成员资料和服务器生命周期事件。Hub 为每个连接维护有效服务器成员集合，服务器事件只发送给对应服务器成员；平台管理员未显式加入时也不订阅内容事件。`server_added` 和 `server_removed` 按目标账号发送并同步更新订阅。WebSocket 只承担增量通知；每次连接建立后前端先读取全局 Bootstrap，再读取当前服务器 Bootstrap，使首次连接、异常重连和发送队列溢出后的恢复使用同一套 HTTP 权威快照。

客户端在自己加入、切换或离开语音频道，以及当前房间成员加入或离开时，通过已认证的 WebSocket 控制消息请求一次语音状态校准。服务端在 300-500ms 窗口内合并并发请求，调用 LiveKit RoomService 全量读取房间成员；只有结果发生变化时，才向所有业务 WebSocket 广播一次现有 `voice_rooms` 全量快照。控制消息不返回快照，避免向发起请求的客户端重复传输；请求失败静默保留当前状态，后台 15 秒周期校准继续兜底。事件触发后的成员预览应在 2 秒内收敛。

Hub 分别维护可写连接集合和按账号聚合的在线租约。同一账号的多个业务连接独立计数，最后一个租约失效后才离线。服务端每 5 秒发送 WebSocket Ping，Pong 刷新该连接最后活动时间；正常关闭立即移除租约，异常中断则以最后活动时间起最多保留 15 秒，期间同账号重连不会产生状态闪烁。

业务 WebSocket 连接通过查询参数自报 `web`、`electron` 或 `android` 客户端类型，缺失或未知值归一为 `web`。同一账号存在多个连接时，在线快照按 `electron > android > web` 选择一个展示类型；该值不可信，仅供成员列表显示徽章，不进入授权判断。

普通业务事件使用容量为 64 的有界发送队列；队列溢出时主动关闭对应连接，使客户端重连并执行 HTTP 权威快照恢复，不允许静默丢弃后继续迁移状态。在线状态使用容量为 1 的独立最新值缓冲：新完整快照覆盖尚未发送的旧快照，不受普通事件积压影响。Hub 在连接增减时实时广播完整在线账号 ID，并每 15 秒无条件重发当前完整快照，使已建立但曾错过单次广播的客户端自动纠正。该周期广播只校准 Go 进程内的业务连接状态，与 LiveKit 语音房间校准彼此独立。

## LiveKit 边界

- 每个语音频道对应稳定房间名 `guild-{服务器数字ID}-channel-{频道数字ID}`，identity 为 `user-{数字用户ID}`；服务器、频道、显示名称、用户 ID 和有效服务器角色写入参与者属性。
- Go 通过经过签名校验的 LiveKit Webhook 实时更新进程内语音占用状态，并在启动、业务 WebSocket 建立、客户端主动请求和后台周期任务中通过 RoomService 全量校准。后台校准间隔由 `VOICE_RECONCILE_INTERVAL` 控制，默认 15 秒，设为 `0` 可禁用。
- 全量校准失败时保留最后一次有效快照并记录警告；校准成功后仅在快照变化时广播。周期任务不会重叠执行，发现同一账号残留在多个房间时按令牌签发代次保留最新有效连接并移除旧连接；数据库已不存在的频道房间由同一周期任务调用 RoomService 删除，失败后在下一周期重试。
- 同一账号在所有房间中只允许一个语音连接。每次签发令牌时将单调递增的签发代次同时写入服务端目标状态和 LiveKit 参与者属性；令牌有效期内只有最新代次及其目标房间可以加入，旧令牌产生的延迟加入会被服务端移除。进程重启后可从参与者属性恢复代次比较。
- 耳机静音作为当前语音会话的 LiveKit 参与者属性，由已认证的 Go 接口代为更新；客户端监听参与者属性变化并刷新成员列表。新加入者从房间状态获得现有成员的耳机静音状态，参与者离开后状态随之消失，不写入 SQLite。
- 客户端先执行本地耳机与麦克风静音，再请求同步耳机状态。同步失败不回滚本地静音，客户端显示错误并在 LiveKit 重连后重试。
- Go 签发有效期 15 分钟的加入令牌，只授予订阅和麦克风发布能力，禁止 LiveKit DataChannel 发布。
- 语音禁言会同时更新 SQLite 状态与用户当前所在 LiveKit 房间的发布权限；临时封禁、永久封禁、管理员重置密码和账号删除会撤销会话并从当前房间移除参与者。
- 显示名称更新会同步到用户当前所在 LiveKit 房间。客户端角色排序优先使用业务 WebSocket 的最新用户资料。
- LiveKit 仅承担媒体和连接质量，不保存账号、消息、权限或提示音设置；自定义提示音文件由浏览器 IndexedDB 承载，不上传到 LiveKit。

## 数据模型

SQLite 在应用启动时执行幂等建表和兼容迁移，主要实体为：

- `users`：全局登录名、显示名称、bcrypt 密码哈希、平台管理员和停用/删除状态；删除行作为匿名关联占位。
- `guilds`：服务器名称、唯一所有者、创建者和时间。
- `guild_members`：服务器与用户成员关系、管理员/成员角色、服务器级禁言、永久封禁和临时封禁截止时间。
- `sessions`：会话令牌 SHA-256 哈希、用户、30 天过期时间。
- `invites`：邀请码 SHA-256 哈希、可选原码、最大/已使用次数、过期与撤销时间。
- `channels`：所属服务器、文字或语音类型、服务器内同类型唯一名称、文字消息保留数量或语音码率及创建/更新时间。
- `messages`：文字频道、用户、纯文本内容和发送时间；删除频道时级联删除。
- `channel_read_states`：用户与文字频道的最后已读消息 ID；删除用户或频道时级联删除。
- `audit_logs`：重要管理操作的操作者、可选目标、可选服务器 ID、动作、详情和时间；目前没有审计日志查询界面。

SQLite 启用 WAL、外键和 5 秒 busy timeout，并将连接池限制为单连接。消息写入与对应文字频道的超额清理在同一事务完成；频道保留数量降低时也会立即事务性删除该频道超额旧消息。文字和语音频道分别限制为最多 50 个，并禁止删除最后一个同类型频道。

从旧单服务器数据库升级时创建默认服务器“Celery Web Speak”，迁移现有账号角色和禁言状态到平台管理员与服务器成员关系，为全部频道补充服务器归属，并保留账号、会话、邀请码、频道、消息、已读和审计记录。旧 `temporary_bans` 数据迁移到默认服务器成员记录后删除该表。更早的单频道结构仍先执行原有频道迁移；当前兼容迁移完成后 `PRAGMA user_version` 保持为 `3`，多服务器结构通过列和表存在性幂等识别。

账号删除采用事务性墓碑而非物理删除，以维持消息、邀请码和审计日志的外键关系。事务校验操作者与目标、保护最后一名平台管理员，并要求先转让或删除目标账号拥有的服务器；随后将登录名替换为基于用户 ID 的内部唯一值，将显示名称改为“已删除用户”，清空可认证密码并设置删除时间，同时删除会话和频道已读状态。登录、启动数据和成员管理查询均排除已删除行；消息查询通过删除状态返回匿名发送者。审计详情保存删除前登录名快照，原登录名可立即重新使用。

## 邀请码与消息分页

- 注册校验始终使用邀请码哈希，不使用可回查原码进行匹配。邀请码消费和用户创建位于同一事务。
- 邀请码管理列表每页最多 30 条，使用 Base64URL 编码的不透明游标。有效记录按到期时间升序，其余记录按创建时间降序。
- 邀请码响应在空列表时返回 `[]`；前端仍将非数组值兼容为空数组。撤销保持记录，永久删除移除记录，两者均写入审计日志。
- 消息列表以文字频道 ID 为必需作用域，接受 `before` 消息 ID 与最多 100 条的 `limit`，前端固定使用 50 条。查询多取一条判断 `hasMore`，返回结果按时间正序排列。
- 启动数据按文字频道计算未读数量并返回该频道当前最新消息 ID。当前频道到达底部后提交最后已读消息 ID；消息因保留策略被删除不回退已读 ID。前端处理实时消息时将未读数量限制在频道保留数量内，频道设置变更时再次收紧该上限。
- 单条消息限制 1-2,000 个字符；进程内限流器允许每名用户 10 秒内发送 8 条。限流状态不写入 SQLite。

## 认证与安全边界

- 登录会话通过 30 天有效的 HttpOnly Cookie 传递，生产默认启用 Secure，SameSite 为 Lax；服务端只保存令牌哈希。
- WebSocket 必须携带有效会话，并校验 `Origin` 是否命中 `TRUSTED_ORIGINS`；未配置列表时仅接受同主机来源。
- JSON 请求体上限 64 KiB，拒绝未知字段和同一请求体中的额外 JSON 对象。
- HTTP 服务配置请求头、读写和空闲超时，并设置 CSP、Permissions-Policy、Referrer-Policy 与 `X-Content-Type-Options`。CSP 的 `script-src` 仅允许同源脚本及 WebAssembly 编译所需的 `'wasm-unsafe-eval'`，不开放 JavaScript 字符串求值所需的 `'unsafe-eval'`。
- 日志使用 Go `slog` JSON 输出；应用不记录密码、会话原始令牌或邀请码哈希。

## 构建、发布与部署

Dockerfile 使用 Node 22 构建 Vue 产物，再使用 Go 1.26 将 `internal/webui/dist` 嵌入单个 Go 可执行文件，最终运行层为 Alpine 3.23 非 root 用户。应用镜像包含 `/api/health` 健康检查。

推送 `v*` Git 标签或手动运行 GitHub Actions 会使用 Buildx 构建 `linux/amd64` 镜像，并向 GHCR 同时推送版本标签和 `latest`。生产 `compose.yml` 只拉取预构建镜像；`compose.build.yml` 仅用于开发机现场构建。

生产 Compose 持久化 `app-data`（SQLite）和 `caddy-data`（ACME 账号、TLS 证书与私钥）。LiveKit 配置由环境变量注入且房间状态是临时的，不挂载持久卷。应用和 LiveKit 信令分别仅绑定到宿主机 `127.0.0.1:${APP_HTTP_PORT}` 与 `127.0.0.1:${LIVEKIT_HTTP_PORT}`（默认 8080 与 7880，仅供调试），媒体端口直接对外开放。Gateway 启用时独占宿主机 80 和 `HTTPS_PORT`；LiveKit TCP、UDP 媒体端口均支持通过环境变量自定义。

## 稳定性与扩展限制

- 应用容器提供健康检查并配置 `restart: unless-stopped`；LiveKit 使用官方镜像和相同重启策略，Compose 只等待其进程启动，不执行媒体可用性探测。
- Go HTTP 服务支持 15 秒优雅关闭。业务 WebSocket 使用 5 秒心跳、15 秒在线租约、有界普通事件队列和独立的在线快照最新值缓冲；LiveKit Client 开启自动重连。
- LiveKit Webhook 是语音占用变化的低延迟主链路，默认每 15 秒执行的 RoomService 全量校准用于修复漏传事件或进程内状态漂移；查询失败不会清空当前成员列表。
- 客户端事件触发的语音校准使用服务端全局防抖合并，避免同一次成员变化被房间内多个客户端重复查询和广播。端到端测试要求频道切换后旧频道成员预览在 2 秒内移除切换者。
- LiveKit 麦克风使用 Opus 单声道、回声消除与噪声抑制，并明确请求关闭浏览器自动增益控制；DTX 默认开启，并可由当前浏览器全局切换。语音 RED 默认开启，背景音固定关闭 DTX 且 RED 默认关闭，两类 RED 均可按频道独立配置。用户切换 DTX 或管理员修改码率/RED 后，客户端在麦克风允许发送时重新发布受影响的本地音轨。
- UDP receive buffer 通过仓库提供的 sysctl 配置提升；媒体优先使用 7882/UDP，7881/TCP 为回退。内置 TURN 已关闭，不支持仅允许 443/TCP 的严格企业网络。
- 在线状态、WebSocket Hub、消息限流、语音目标房间和 LiveKit 房间快照均为单实例内存状态。增加多个 Go 或 LiveKit 实例前，必须引入共享协调与状态层，不能直接复制当前 Compose。
- 当前备份范围需覆盖 `app-data` SQLite 卷和 `caddy-data` 证书卷；禁用 Gateway 时证书、反代和主机防火墙由部署方独立管理。
