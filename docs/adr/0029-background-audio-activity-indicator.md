# 语音参与者行的音符指示按背景音真实声音亮起，持续无声音后熄灭变灰

背景音音符此前只看 LiveKit 发布状态（ScreenShareAudio 轨道存在且未静音）就常绿，分享者选择无声源或静默片段时指示失真。决策：音符改为三态——无背景音会话隐藏；会话存在期间常显，检测到真实声音亮起（保持绿色），持续约 5 秒无声音熄灭变灰；分享者暂停（发布轨道静音）同样落入灰色而非隐藏。声音检测在**收听者客户端**对接收到的背景音轨道逐帧做 RMS 能量分析（复用麦克风说话活动监测的同一机制：100ms 轮询、阈值 0.015，仅保持时长参数化为 5000ms），不依赖发布者上报——发布者状态无法反映"真实声音"。指示只反映分享者的声音事实，与收听者本地静音、耳机静音无关（与说话指示同视角）；本地用户自己那一行同样生效，观察视角统一。

## Considered Options

- **发布者侧状态上报**：由分享端把"有无声音"作为参与者属性推给全频道。发布者同样要本地检测，且状态推送有延迟与丢失窗口，还多一层协议；收听者直接分析接收轨道更接近"真实声音"的事实。舍弃。
- **暂停隐藏、仅"播放中静默"变灰**：三态模型分裂成四态，分享者一暂停就完全从界面消失，与"正在分享背景音"的事实矛盾。舍弃。
- **短保持（250ms / 2s）**：250ms 在曲间停顿与对白换气处频繁闪烁；2s 仍偏敏感。5s 覆盖常见曲间停顿，又与"持续没有声音才熄灭"的直觉吻合。舍弃。
- **暂停动作立即熄灭**：把"暂停动作"直接映射为灰色，与"指示反映真实声音"的语义相悖。统一由静默驱动（暂停的轨道产生静默，5 秒后自然熄灭）。舍弃。
- **本地静音也压灰**：把收听者偏好混入分享者状态指示，与说话指示（不受本地静音影响）不一致。舍弃。
