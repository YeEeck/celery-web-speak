# 参与者本地静音以黄色图标指示，替代对方自身状态色，仅实施于语音频道参与者行

按参与者播放控制中的静音状态（麦克风静音 `cws.muted.<uid>`、背景音静音 `cws.backgroundAudioMuted.<uid>`，localStorage 持久化）此前在语音参与者行没有任何显示——本地静音长期生效时，当前用户无从得知「某人一直被我静音」，也看不到自己在操作菜单里的静音动作。决策：参与者行图标簇每条轨道最多一个状态图标，当前用户本地静音某轨道时以**黄色**呈现并替代对方自身状态色（灰色禁麦/聋、绿色音符亮起、灰色音符无声音），取消本地静音后恢复对方自身状态色；黄色指示仅当前用户可见（本地静音本就是本机偏好，不改变该参与者向其他人发送的声音）。图标簇由此形成固定视觉语义分区：灰=对方自身状态、黄=我的本地静音操作、绿=真实声音（背景音亮起）、红=管理状态与错误（既有「已禁言」红字与错误提示不变）。背景音音符随之获得第 4 态：黄色=收听者已本地静音（替代亮起/变灰）。aria/title 文案与操作菜单按钮一致：「你已关闭此人的麦克风声音」「你已关闭此人的背景音」。只实施于语音频道参与者行；浮层与未加入预览列表不显示。音量 0% 不构成静音，沿用「播放音量与本地静音相互独立」（见 voice-participant-action-menu-design）。

## 实现事实

`VoiceParticipant` 已携带 `microphoneMuted` / `backgroundAudioMuted`（voice-session.ts 从 localStorage 读取），行渲染是纯模板 + CSS 改动，不需要动状态层；黄色复用既有 warning 色系 token，不与状态点橙色（在头像上）与等级颜色（在资料卡上）同表面。

## Considered Options

- **红色静音图标**：最初提议的方案，但红色在主列表已负载「已禁言」红字（服务器管理）与错误提示，浮层中又是对方自身静音状态的图标色，再引入红色会形成多重语义。改用黄色。舍弃。
- **灰黄双图标并存**：同一轨道并排两个图标信息最全，但行内视觉笨重，对方自静音变化时图标跳动，「我听不到」的解释也冗余。舍弃。
- **浮层同步显示**：浮层红色已是对方自身状态色，本地静音需另造视觉区分（双图标或改色系），与浮层只读、紧凑的设计冲突；浮层也无本地控制入口。留待后续单独设计。舍弃（本轮）。
- **音量 0% 视为静音**：与既有「播放音量与本地静音相互独立」相悖，会把滑杆操作卷入静音语义。舍弃。
