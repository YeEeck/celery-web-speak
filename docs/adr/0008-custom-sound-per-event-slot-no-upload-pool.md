# 自定义音效按事件独占槽、不引入用户上传池

加入语音、退出语音与新文字消息三类操作提示音新增了"自定义音效"能力。曾在设计中考虑过"用户上传池 + 多事件引用"模型：用户上传一次文件，多个事件可从同一池中各自挑选，被删除时处理引用计数与回退。该模型带来一个完整的「我的音效」列表 UI、引用计数、删除时多事件回退语义——对一个只有 3 个事件、5 个预置的产品体量是过度工程。

最终采用「每事件独占一个上传槽」模型：3 个事件各有独立的 IndexedDB 记录与上传交互；同一个文件想用于多个事件需要分别上传，这是被接受的使用代价。该模型与现存「每事件一个值」的 `localStorage.preset.<event>` 同构、删除语义简单（清一个事件槽即回退到该事件保留的系统预置）、不需要列表 UI、不引入引用计数。

由此换来的代价是用户上传成本和使用成本略高，但换来了存储、UI、回退逻辑的明显简化。
