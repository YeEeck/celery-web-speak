# 重新开启麦克风自动增益控制

之前 ADR 范围内通过 `docs/microphone-auto-gain-design.md`（已删除）把语音发布链的 `autoGainControl` 设为 `false`，理由是浏览器 AGC 的动态升降使"麦克风增益"无法对应稳定、可预期的发送电平。实际运行观察到关闭后同一说话者在一次通话内的电平波动比开启时更明显——真实漂移来源是用户与麦克风的距离和位置，AGC 正是用来抑制这种时间维度漂移的；原设计文档把漂移归因于 AGC 属于因果倒置。

决定把语音发布链的麦克风采集约束改回 `autoGainControl: true`，产品立场从"说话者对自己发送电平的可预期性优先"改为"收听者听到说话声稳定优先"。不向用户暴露 AGC 开关：用户可见的音量调节只有"麦克风增益"一个，AGC 在它之前隐身工作。静音说话提醒的本地 VAD 采集维持 `autoGainControl: false`——VAD 不发布给他人、不涉及收听者体验，且 AGC 会扰动说话判决门槛的边界。

## 修订（2026-08-03）：VAD 采集改回 AGC 开启

原"VAD 维持 AGC 关闭"的决策在实机上被证伪：同一机器同一麦克风下，浏览器（Chrome）遵守 AGC 关闭后 VAD 输入电平过低，libfvad mode 2 按 SNR 门槛永远判不出说话——静音说话提醒与自动状态检测全部失效；而 Electron 的 Chromium 未遵守该约束（回声抑制开启时强推 AGC），VAD 输入被抬到过响，提醒异常灵敏并反复触发。同一约束在两个运行环境表现成镜像故障，说明"AGC 关闭"不能作为 VAD 输入电平的可靠前提，电平归一化必须交给浏览器 APM。VAD 采集约束改为与发布链一致：`autoGainControl: true`（回声抑制与降噪保持开启）。

随之修整领域术语：`CONTEXT.md` 的"麦克风增益"从"固定倍率、通话期间不会自动改变"重写为"音量倍率基准，不等于最终发布到远端的响度"；新增"发送电平"词条独立指代实际发布响度，把原本寄生在"麦克风增益"上的"发送电平随谁变"语义真空显式命名，避免读文档者把两者再次混为一个概念。
