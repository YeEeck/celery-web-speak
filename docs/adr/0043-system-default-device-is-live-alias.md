# 系统默认设备是活别名；设备变化先解析再重绑

插拔、系统改默认、睡眠唤醒时，本机采集和播放经常停在旧路由上：浏览器 `'default'` 的 ID 在改指后通常不变，现有逻辑只在设备 ID 从名单消失时才降级，且说话检测引擎对同一 ID 幂等。决定：**系统默认设备**是随系统改指而改指的活别名；设备变化由 `devicechange`、任一当前采集轨 `ended`、页面 `freeze`→`resume` 触发一次全局解析，按解析结果决定是否重绑。首选某一台具体设备被拔出时仍回退到系统默认、不覆盖首选、会话内不自动切回。加入语音期间说话检测引擎、应用提示音与背景音播放跟会话设备，不跟解析后的首选。不离开语音房间。切标签、失焦、混音上下文挂起只恢复播放（ADR-0005），不重绑。自动重绑失败不 toast。输入/输出默认由浏览器分别解析，产品不引入通讯默认与多媒体默认。

## Considered Options

- **把「系统默认」当选中当下的那台硬件**：系统改默认后继续钉死旧硬件，正是本问题。否决。
- **每次 `devicechange` 都重建采集**：插一台不当默认的 USB 声卡也会断麦。否决。改为比较默认指向的身份（`groupId`、否则标签）；比不出则重绑。
- **用 `visibilitychange` 或 AudioContext 挂起当睡眠入口**：切标签同样触发，会无故重建采集。否决。
- **断开房间再加入**：对端看到进进出出，通话可能被挂断。否决。
- **首选具体设备在会话中回来就自动切回**：突然改音频路径。否决；离开后再按首选。
- **自动路径失败弹 toast / 写点选错误**：睡眠醒来会连弹。否决。
