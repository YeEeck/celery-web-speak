# 接收端自动音量平衡采用逐参与者播放端 AGC，走 setWebAudioPlugins 最小侵入路径

远端语音参与者的发送电平差异大（各人"麦克风增益"0%-300% 不同、说话习惯与距离不同），收听者听感忽大忽小。决策：新增"自动音量平衡"全局偏好（默认关闭、仅本机），接收端对每位远端语音参与者的麦克风轨道做播放端 AGC 归一化——按实测接收响度向固定目标电平（-20 dBFS）缓慢收敛，小声放大、大声压低，叠加在"按参与者播放控制"（手动音量=每人的目标偏置）与"扬声器音量"（总音量）之上；静音/聋归零；不改变该参与者向他人发送的声音。参照物为 TeamSpeak 3 的 "Automatic voice volume leveling"（官方 changelog 直称 playback AGC，逐用户维护增益状态）。

实现路径：沿用现有 LiveKit `webAudioMix` 播放链，通过 `RemoteAudioTrack.setWebAudioPlugins([analyser])`（SDK 官方实验扩展点，`@internal @experimental`，版本钉死 2.20.1）在**手动增益之前**插入测声节点；AGC 修正系数不进新节点，而是经现有 `participant.setVolume` 应用——`applyVolume(userId)` 保持唯一应用点。原型验证（真实 LiveKit 环境，Chromium）确认：插件位确实在手动增益之前（`setVolume(0.25)` 前后 analyser 读数比 ≈1.00）、静音读数归零、detach/attach 生命周期重建正常、清空/装回插件无异常；同上下文对同一轨道二次建源实测无浏览器"一次一源"约束（旁路 fork 亦可，但插件位单链更干净）。

合成公式（dB）：`有效增益 = clamp(T − L, −12, +12) + manualDb`，最终应用 `10^(有效增益/20) × 扬声器音量`。其中 T=-20 dBFS（固定目标，实测典型接收电平恰 ≈ -20dBFS）；**钳制 ±12dB 只作用于电平修正项**，手动偏置在钳制之外相乘——01 标定发现：若偏置在钳制内，manual=0.3（-10.5dB）叠加大声说话（-8dB 修正）合计 -18.5dB 会被截断，用户显式偏置受损。参数策略：快 attack（τ≈300ms）/ 慢 release（τ≈2s）防抽吸；低于 -55dBFS 底噪阈值冻结增益（不泵不漂移，防无限放大底噪）；新参与者从 0dB 起步，静音/聋期间冻结、恢复说话从冻结值继续收敛（避免开口跳变）；控制率 5Hz。AGC 模拟器（8 项断言全过）验证收敛、钳制、冻结与 attack/release 不对称性。

控制面：设置面板"音频 → 输出"页全局开关（播放端偏好，与"扬声器音量"同页），默认关闭，localStorage `cws.autoVoiceBalance` 仅本机生效、切换即时生效；参与者菜单在开启时显示静态提示行"自动音量平衡已开启，音量滑杆作为相对偏置"（不显示动态生效电平——每秒变化的值只会制造噪音感）。范围：仅麦克风轨道；背景音（应用背景音/ScreenShareAudio）不参与——音乐不该被归一化。划出范围：逐参与者开关、发送端分享响度、音乐频道豁免（TS 3.5.1 行为，本产品无"音乐频道"概念）。

与发送端 AGC（autoGainControl）不打架：发送端 AGC 作用于采集端（编码前），接收端平衡作用于播放端（解码后），接收端增益纯本地、不反馈回发送方测量——串联开环而非闭环，不会追逐振荡；发送端 AGC 消除同一说话人自身的电平波动，接收端平衡消除说话人之间的残余差异（尤其各人"麦克风增益"不同造成的发送电平差）。

## Considered Options

- **setWebAudioPlugins 最小侵入（采用）**：改动全部落在现有播放链外，设备切换/静音/聋/全局音量零改动；风险是实验 API（版本钉死，升级需回归），原型已验证可行。
- **旁路 fork 测声**：自建第二 `MediaStreamSourceNode` 读电平。实测该 Chrome 无"一次一源"约束、fork 出数据——可行但会为每个参与者多建一条并行图边，不如插件位单链干净；作为插件位失效时的轻量备选。
- **接管播放图**：弃用 `webAudioMix`，自建 source→analyser→autoGain→destination，音量/静音/聋/输出设备全自管。控制力最强但重写现有播放路径（设备切换、输出路由、重连恢复、应用音分离），爆炸半径大；未采用。
- **发送端分享响度**（data channel/attributes）：语义上锁定"接收者层面"，且接收端实测才是实际听到的响度；未采用。

## 修订记录

- **2026-08-05（01 标定）**：钳制语义精化——±12dB 只作用于电平修正项 `clamp(T−L)`，手动音量偏置在钳制之外相乘（原拟定"AGC 收敛到 目标×手动音量"未区分钳制边界，模拟器实测偏置会被截断）。
- **2026-08-05（实现审查）**：最终应用增益在合成层经既有 `clampVolume` 按 MAX_VOLUME=3 做安全上限钳制（防削波，与功能关闭前的钳制行为一致）——平衡修正项在 ±12dB 内，但 manual×output 接近上限时修正超出部分被截断，属既有安全上限语义。
