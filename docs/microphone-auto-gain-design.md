# 麦克风自动增益策略设计

## 背景

当前语音通话在首次采集麦克风和重新发布麦克风时都明确请求浏览器开启自动增益控制（AGC）。浏览器先动态拉升或压低采集电平，应用再通过 Web Audio `GainNode` 应用用户设定的麦克风增益。

这使固定的麦克风增益无法对应稳定、可预期的发送电平。AGC 来自最初的语音客户端实现，项目内没有记录开启它的产品依据、效果验证或运行时检查。

## 已确认决策

- 麦克风增益是用户设定的固定倍率，其可预期性优先于自动响度归一化。
- 所有用于语音发布的麦克风采集都请求 `autoGainControl: false`，不提供用户开关。
- 使用普通布尔约束尽力关闭 AGC，不使用会在不支持时导致采集失败的 `{ exact: false }`。浏览器无法确认或落实该约束时不阻止通话，不增加产品错误提示。
- 回声抑制和降噪继续默认开启，并保留现有用户设置。
- 麦克风增益继续使用 0%-300% 范围和 100% 默认值，不迁移或改写用户已保存的数值。
- 直接切换默认策略，不做无法产生可比数据的灰度或 A/B 实验。

## 目标与非目标

本次目标是消除同一麦克风在一次通话中被 AGC 动态拉升或压低造成的电平波动，使用户设定的麦克风增益保持固定语义。

本次不承诺自动拉齐不同参与者的响度；不同麦克风、操作系统输入电平和说话距离仍会产生差异。收听者继续通过现有的按参与者麦克风音量调节差异。

本次不新增自动电平模式、峰值表、削波提示或限制器，不调整应用背景音和远端播放链路。静音说话提醒的本地 VAD 采集已单独关闭 AGC，保持现状。

## 处理链与场景

发送链收敛为：

`浏览器采集（请求回声抑制、降噪和 AGC 关闭） -> 固定麦克风增益 -> LiveKit 编码与发布`

同一份麦克风采集选项应用于以下场景，避免各路径产生不同默认值：

- 麦克风开启状态加入语音时的首次发布。
- 以麦克风静音或耳机静音状态加入后，首次恢复麦克风。
- 主动静音、耳机静音或管理员禁言结束后重新发布麦克风。
- 切换传输模式或其他发布参数后重新发布麦克风。
- 切换输入设备。LiveKit 2.20.1 会保留原音轨的其他采集约束，只替换 `deviceId`。

## 实现与验收

- 首次发布和重新发布复用同一份麦克风采集选项，选项明确包含 `autoGainControl: false`。
- 不新增 UI、本地存储键或服务端字段。
- 静态检查确认语音发布代码不再请求开启 AGC，并保留 VAD 采集已有的关闭策略。
- 自动验证覆盖共享采集选项，防止首次发布与重新发布再次分叉；前端类型检查和生产构建必须通过。
- 人工验收使用真实麦克风观察同一发送者的电平稳定性，并检查浏览器报告的实际 `autoGainControl` 设置。该观察不作为不支持浏览器的通话门槛。
