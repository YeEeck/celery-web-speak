# Celery Web Speak 受控多服务器设计

> 状态：方案已确认，尚未实施。
>
> 设计日期：2026-07-24。
>
> 当前实现基线：v0.3.9，单部署、单个公开服务器、多文字和语音频道。

## 背景

当前产品中的“服务器”实际是单个部署的全部用户和频道。所有登录用户可见全部成员、频道、在线状态和语音房间；频道只能隔离文字消息和媒体房间，不能成为群体之间的权限边界。

这使同一套部署难以同时服务互不相关的多个固定群体。为每个群体部署一套完整 Compose 可以获得强隔离，但会重复占用 Caddy 入口、LiveKit 媒体端口、SQLite 数据卷、升级和备份流程。

本设计在一个 Go 应用、SQLite 数据库和 LiveKit 节点中引入多个逻辑“服务器”。用户界面沿用 Kook/Discord 的术语，称为“服务器”；代码和数据库使用 `guild`，以避免与 Go `Server`、物理主机和部署实例混淆。

该模型是受控式多服务器：平台管理员创建服务器并指定所有者，服务器所有者和管理员负责成员及频道。普通用户不能自行创建服务器，也不能通过服务器邀请码或公开目录自行加入。

## 目标

- 一套部署支持多个彼此隔离的用户群体。
- 每个用户只看到自己已加入服务器的内容和实时状态。
- 平台管理员可以管理所有服务器的元数据、生命周期和全局账号，但不自动获得服务器内容访问权。
- 平台邀请码只用于创建全局账号，不绑定任何服务器。
- 服务器所有者和管理员通过完整登录名直接把已有账号加入服务器。
- 左侧服务器栏成为服务器切换器，复用现有 72px 服务器栏布局。
- 保持单 Go 进程、单 SQLite 和单 LiveKit 节点的部署模型，不引入新的基础设施。
- 保持一个账号在全平台至多一个语音频道连接的现有规则。

## 非目标

- 普通用户创建、删除或公开发现服务器。
- 服务器邀请码、加入链接、公开服务器目录或待审批的成员申请。
- 私密频道、频道成员名单、频道级角色或私聊。
- 自定义角色、权限位、服务器分类、手动排序或频道分类。
- 服务器图标上传、横幅、服务器昵称、用户头像上传或文件存储。
- 按服务器计费、配额、独立数据库、独立域名或独立部署。
- 多 Go 实例、多 LiveKit 节点和水平扩展一致性设计。
- 用逻辑服务器隔离替代操作系统、进程或物理机级隔离。

## 术语与边界

```text
Celery Web Speak 平台 / 单次部署
  |- 全局账号、登录会话、平台邀请码、平台管理员
  |
  |- 服务器 A (guild)
  |    |- 成员、所有者、服务器管理员、服务器级禁言和封禁
  |    |- 文字频道
  |    `- 语音频道
  |
  `- 服务器 B (guild)
       |- 成员、所有者、服务器管理员、服务器级禁言和封禁
       |- 文字频道
       `- 语音频道
```

### 平台

平台是一个部署实例。它拥有全局账号、登录 Cookie、平台邀请码、平台管理员和应用级安全控制。平台不是普通用户可切换的业务服务器。

### 服务器

服务器是用户群体的逻辑边界。成员关系、频道、成员列表、在线状态、未读、消息、语音房间、邀请码以外的管理行为均以服务器为作用域。不同服务器的频道名称可以相同。

### 频道

频道继续分为文字和语音两类，且必须归属一个服务器。一个服务器内的全部活跃成员默认可见和可访问其全部频道；首期不实现私密频道。

## 权限模型

### 全局账号状态

每个账号有独立于服务器成员关系的全局状态：

- `platform_admin`：平台管理员，由现有启动管理员及平台管理界面维护。
- `suspended`：平台级停用状态。被停用后不能认证，也不能访问任何服务器。
- `deleted`：账号删除墓碑。继续沿用现有匿名化和会话撤销规则。

`platform_admin` 不等同于任一服务器的成员或所有者。平台管理员不会因为平台权限自动出现在所有服务器成员列表、在线状态或 LiveKit 房间中。

### 服务器角色

服务器成员有三种有效角色：

- 所有者：每个服务器恰好一名，由 `guilds.owner_user_id` 表示；该用户也必须存在对应成员记录。
- 管理员：由所有者或平台管理员任命，可管理频道和普通成员。
- 成员：可访问服务器内公开频道并参与文字和语音聊天。

成员表只保存 `admin` 或 `member`。读取和授权时，当 `guilds.owner_user_id == user_id`，对外呈现有效角色 `owner`。这样所有权转移只更新一个字段，同时保留成员关系和审计记录。

### 成员管理规则

- 所有者不能被服务器管理员移出、禁言、封禁或降级。
- 服务器管理员不能管理其他服务器管理员；所有者可以管理管理员。
- 平台管理员可以在未加入时更换所有者；其他成员操作必须先显式加入服务器。平台操作必须写入平台和服务器审计日志。
- 管理员添加成员时只接受完整登录名的精确匹配，不提供模糊搜索、自动补全或全平台账号列表。
- 账号加入服务器后立即成为成员，不要求接受邀请。在线账号立即收到实时事件；离线账号下次登录时看到该服务器。
- 成员和管理员可以主动离开服务器；所有者不能主动离开，必须由平台管理员先转让所有权或删除服务器。
- 平台管理员加入服务器后获得服务器管理员角色，可以主动离开；离开不影响平台管理员权限。

### 禁言、踢出和封禁

- 文字禁言、语音禁言、临时封禁和永久封禁均为服务器级状态，不影响用户在其他服务器的访问。
- 踢出删除成员关系，之后可以被重新添加。
- 封禁保留成员记录但标记为不可访问，防止管理员在封禁期间重新添加该账号。
- 临时封禁到期后恢复原成员关系和角色；客户端在下一次权威快照或到期事件后重新显示该服务器。
- 永久封禁必须由有权操作的人显式解除。
- 平台级停用仍然阻止登录和全部服务器访问，独立于服务器封禁。

## 用户流程

### 平台注册与登录

1. 平台管理员创建平台邀请码。
2. 新用户使用邀请码注册全局账号；邀请码消费和账号创建在同一事务中完成。
3. 注册后不自动加入任何服务器。
4. 用户登录成功后读取全局启动数据和其可见服务器列表。
5. 没有任何可访问服务器的普通用户进入空状态，而不是展示无权限服务器。

空状态文案保持简洁：`尚未加入任何服务器，请联系服务器管理员将你加入服务器。`

已有账号不能再次使用平台邀请码注册。平台邀请码不是服务器加入凭证，不提供“输入邀请码后加入某个服务器”的行为。

### 创建服务器

平台管理员在左侧服务器栏的新增入口或平台管理控制台中创建服务器，并在同一表单内指定已有账号作为所有者。创建输入包括服务器名称和所有者登录名。

创建事务必须依次完成：

1. 验证操作者为平台管理员，所有者账号存在且未停用。
2. 创建服务器记录。
3. 创建所有者成员记录。
4. 创建默认文字频道“文字聊天”。
5. 创建默认语音频道“语音频道”。
6. 写入创建服务器和指定所有者审计日志。

服务器名称允许重复，长度为 1-64 个字符，去除首尾空白后不能为空。服务器图标首期由名称生成稳定的首字与颜色，不保存上传文件。

### 添加与移出成员

服务器所有者或管理员在成员管理界面输入完整登录名。服务端确认操作者角色、目标账号存在、目标未被该服务器封禁后，创建成员关系并发送 `server_added` 实时事件。

移出成员时：

- 立即撤销该账号对服务器 HTTP、WebSocket 和 LiveKit Token 的访问。
- 如果目标正在该服务器语音频道中，立即移除其 LiveKit 参与者。
- 向目标的全部业务 WebSocket 发送 `server_removed`；当前查看该服务器的客户端清除频道和本地缓存，切换至下一个可访问服务器或空状态。
- 不删除目标在该服务器的历史消息；消息显示名称仍遵循账号删除前的现有规则。

### 服务器所有权与删除

- 仅平台管理员可以转让所有权。新所有者必须是该服务器的活跃成员；平台在同一事务中更新所有者并保留旧所有者的管理员成员关系。
- 仅平台管理员可以删除服务器。删除前显示服务器名称、成员数量、频道数量和不可恢复说明，并要求输入服务器名称确认。
- 删除服务器会级联删除频道、消息、已读状态和服务器成员关系；全局账号、会话和平台邀请码不受影响。历史审计记录保留服务器名称和 ID 快照，不随服务器删除。
- 平台管理员删除账号前必须先转让该账号拥有的全部服务器或删除这些服务器，避免产生无所有者服务器。

### 左侧服务器栏

桌面和宽屏平板的 72px 左栏展示服务器切换器：

```text
[当前服务器图标]
[已加入服务器图标]
[已加入服务器图标]
-----------------
[平台管理员：创建服务器]
[连接状态]
```

- 普通用户只看到有效成员关系所属的服务器，按加入时间升序排列；不提供手动排序。
- 平台管理员看到全部服务器，已加入服务器正常显示，未加入服务器使用低强调样式和“仅管理信息”提示。
- 平台管理员点击未加入服务器时打开服务器概览，只展示允许的元数据和“加入服务器”命令，不加载内容、成员或频道。
- 服务器图标上的未读标记只对已加入服务器展示。
- 服务器名称和成员列表均只在当前服务器内容区显示，避免跨服务器信息泄漏。
- 移动端当前隐藏服务器栏。频道抽屉头部增加服务器切换入口，行为与桌面栏一致；不在窄屏并排显示服务器栏和频道栏。

### 频道、未读与本地状态

- 用户一次只查看一个当前服务器和该服务器中的一个文字频道。
- 切换服务器后重新读取该服务器 Bootstrap；频道、成员、已读、语音房间和当前文字频道消息不与其他服务器混合。
- 文字频道草稿、滚动位置和活动频道 `localStorage` 键增加服务器 ID 前缀，例如 `cws.server.12.channelDraft.45`。
- 未读状态仍按用户和文字频道持久化。全局启动数据额外返回每个已加入服务器的未读汇总，用于左栏标记。
- 同名频道在不同服务器没有冲突；服务器内同类型频道名称保持不区分大小写唯一。

### 语音切换行为

一个账号在全平台仍只允许一个语音频道连接。用户在服务器 A 的语音频道中时切换浏览服务器 B，不会自动断开 A 的语音连接；底部连接面板持续显示服务器 A 和频道名称。

- 在任一服务器点击加入新的语音频道时，新的连接取代旧连接。
- 当前所连服务器的成员关系被移除、被封禁、服务器被删除或会话被撤销时，客户端和服务端立即断开语音。
- 切换服务器后，语音 Store 保留已连接服务器和频道的独立摘要，不能依赖当前服务器频道列表查找该信息。
- LiveKit 房间成员、频道码率和 RED 设置始终读取连接目标频道的服务器数据。

## 数据模型

### 全局表

`users` 保留登录名、显示名称、密码哈希、删除墓碑和创建时间。现有全局 `role`、文字/语音禁言和封禁字段迁移为平台状态或服务器成员状态：

- `role` 替换为 `is_platform_admin`。首期不保留全局频道管理员角色。
- `permanently_banned` 迁移为平台 `suspended_at` 或等效全局停用标记，保持其原有“无法登录全平台”的语义。
- `voice_muted`、`text_muted` 和临时封禁迁移到默认服务器成员记录。

`sessions` 继续只关联全局账号，不绑定服务器。平台邀请码继续使用现有 `invites` 表和哈希校验逻辑，不增加 `guild_id`。

### 服务器表

```sql
CREATE TABLE guilds (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL COLLATE NOCASE,
  owner_user_id INTEGER NOT NULL REFERENCES users(id),
  created_by INTEGER NOT NULL REFERENCES users(id),
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

CREATE INDEX guilds_owner_user_id ON guilds(owner_user_id);
CREATE INDEX guilds_created_at_id ON guilds(created_at, id);

CREATE TABLE guild_members (
  guild_id INTEGER NOT NULL REFERENCES guilds(id) ON DELETE CASCADE,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  role TEXT NOT NULL CHECK(role IN ('admin', 'member')),
  voice_muted INTEGER NOT NULL DEFAULT 0,
  text_muted INTEGER NOT NULL DEFAULT 0,
  permanently_banned INTEGER NOT NULL DEFAULT 0,
  temporary_ban_until TEXT,
  joined_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  PRIMARY KEY(guild_id, user_id)
);

CREATE INDEX guild_members_user_guild ON guild_members(user_id, guild_id);
CREATE INDEX guild_members_guild_role ON guild_members(guild_id, role, user_id);
```

所有者不是 `guild_members.role` 值。读取成员资料时，服务端根据 `guilds.owner_user_id` 映射为 JSON `role: "owner"`；其余成员映射为 `admin` 或 `member`。

### 频道和关联数据

`channels` 增加不可空 `guild_id` 外键，并把唯一约束从 `UNIQUE(type, name)` 改为 `UNIQUE(guild_id, type, name)`。频道上限从全局每类型 50 个改为每服务器、每类型 50 个。

`messages` 和 `channel_read_states` 通过 `channel_id` 间接归属服务器；查询必须联结 `channels.guild_id` 和 `guild_members`，不能仅依赖全局频道 ID。

`audit_logs` 增加可空 `guild_id`：平台操作写 `NULL`，服务器创建、频道、成员和服务器级审核操作写入对应服务器 ID。历史审计记录保持 `NULL`。

服务器级禁言和封禁由 `guild_members` 保存。被封禁成员仍保留记录，踢出成员才删除记录；这样可同时表达“不可重新添加”和“临时封禁到期恢复成员关系”。

## 迁移策略

现有部署升级时必须保留账号、会话、平台邀请码、频道、消息、已读和审计数据。迁移由 SQLite 幂等升级函数完成，并在单个数据库事务中提交结构重建和数据复制。

1. 创建默认服务器，名称固定为“Celery Web Speak”。
2. 找出最早创建的现有 `server_admin` 作为默认服务器所有者和平台管理员。
3. 其余现有 `server_admin` 迁移为平台管理员和默认服务器管理员。
4. 现有 `channel_admin` 迁移为默认服务器管理员。
5. 现有未删除普通用户迁移为默认服务器成员；已删除账号墓碑不创建成员关系。
6. 现有频道写入默认服务器 ID；消息和已读状态通过频道关系自然继承。
7. 现有文字/语音禁言和临时封禁复制到默认服务器成员状态。
8. 现有永久封禁保持为平台级停用，延续原有全平台禁止登录语义。
9. 现有平台邀请码、会话和账号删除墓碑保持不变。
10. 历史审计日志保留，`guild_id` 为空；迁移过程写入一条平台审计记录。

SQLite 对现有约束的修改需要重建受影响的表。迁移前的生产备份仍是部署方责任；应用不提供数据库降级迁移。

## API 设计

### 全局启动与平台接口

`GET /api/bootstrap` 不再返回全量频道、成员或语音房间，只返回：

```json
{
  "user": {
    "id": 7,
    "username": "alice",
    "displayName": "Alice",
    "isPlatformAdmin": false
  },
  "servers": [
    {
      "id": 12,
      "name": "项目组",
      "joined": true,
      "role": "admin",
      "unreadCount": 3
    }
  ]
}
```

平台管理员响应额外包含未加入服务器的元数据，但不含频道、成员和未读：

```json
{
  "id": 18,
  "name": "朋友",
  "joined": false,
  "ownerUserId": 22,
  "memberCount": 6,
  "createdAt": "..."
}
```

平台接口建议为：

```text
GET    /api/platform/servers
POST   /api/platform/servers
PATCH  /api/platform/servers/{serverID}/owner
DELETE /api/platform/servers/{serverID}
POST   /api/platform/servers/{serverID}/join

GET    /api/platform/invites
POST   /api/platform/invites
DELETE /api/platform/invites/{inviteID}
DELETE /api/platform/invites/{inviteID}/permanent

GET    /api/platform/users
POST   /api/platform/users
PATCH  /api/platform/users/{userID}/suspend
DELETE /api/platform/users/{userID}
```

`POST /api/platform/servers/{serverID}/join` 创建平台管理员自己的服务器管理员成员关系，并记录平台管理员加入服务器审计事件。该接口不会代替普通成员的服务器添加流程。

### 服务器作用域接口

```text
GET    /api/servers/{serverID}/bootstrap
PATCH  /api/servers/{serverID}
POST   /api/servers/{serverID}/leave

GET    /api/servers/{serverID}/members
POST   /api/servers/{serverID}/members
PATCH  /api/servers/{serverID}/members/{userID}/role
PATCH  /api/servers/{serverID}/members/{userID}/mute
POST   /api/servers/{serverID}/members/{userID}/kick
PATCH  /api/servers/{serverID}/members/{userID}/ban
DELETE /api/servers/{serverID}/members/{userID}/temporary-ban

POST   /api/servers/{serverID}/channels
PATCH  /api/servers/{serverID}/channels/{channelID}
DELETE /api/servers/{serverID}/channels/{channelID}
GET    /api/servers/{serverID}/channels/{channelID}/messages
POST   /api/servers/{serverID}/channels/{channelID}/messages
DELETE /api/servers/{serverID}/channels/{channelID}/messages/{messageID}
POST   /api/servers/{serverID}/channels/{channelID}/read
POST   /api/servers/{serverID}/channels/{channelID}/voice/token
PATCH  /api/servers/{serverID}/channels/{channelID}/voice/state
```

服务器成员添加请求使用完整登录名：

```json
{ "username": "alice" }
```

不要提供用户枚举接口给服务器所有者或管理员。目标不存在、无权管理目标或目标已在服务器中时，响应使用一致的受控错误信息；日志保留真实原因供平台管理员诊断。

### 授权规则

- 路径中的 `serverID` 先解析，再加载当前账号对应的服务器成员关系。
- 普通用户对未加入服务器访问返回 `404`，不泄露服务器存在。
- 平台管理员对未加入服务器内容接口返回 `403 server_membership_required`，因为其已能在平台管理中看到服务器元数据。
- 频道、消息和已读接口必须同时验证 `channel.guild_id == serverID`。单独知道频道或消息数字 ID 不能越过服务器边界。
- `requirePlatformAdmin` 只保护平台接口；它不替代 `requireGuildMember`，也不自动绕过内容读取权限。
- 服务器成员操作中，先验证操作者有效角色，再验证目标成员在同一服务器和可被该角色管理。

## HTTP Bootstrap 与前端状态

### 服务器 Bootstrap

`GET /api/servers/{serverID}/bootstrap` 返回当前服务器上下文：

- 当前账号在该服务器的有效角色和禁言状态。
- 当前服务器成员资料和该服务器在线 ID。
- 当前服务器按创建顺序排列的频道。
- 当前用户在该服务器文字频道中的已读状态和未读数。
- 当前服务器语音房间快照。
- 当前活动文字频道的最新消息第一页按现有策略另行读取。

前端 `app` Store 分为两层：全局账号/服务器摘要状态，以及当前服务器上下文状态。切换服务器时清空后者并重新 Bootstrap，不能复用其他服务器的成员、频道或语音房间快照。

### 前端服务器状态

- 当前服务器 ID 保存为 `cws.activeServerId`。
- 当前文字频道、草稿和滚动位置的键带服务器 ID。
- 登录后优先恢复已保存且仍可访问的服务器；否则选择服务器列表第一项。
- 被移出当前服务器时选择下一个已加入服务器；不存在时展示空状态。
- 平台管理员点击未加入服务器不会设置当前内容服务器，只打开平台服务器概览。
- 个人资料、音频、主题和提示音仍是账号/浏览器本地设置，不复制到服务器成员关系。

## WebSocket 与在线状态

业务 WebSocket 继续使用一个全局连接 `/api/ws`，而不是每次切换服务器重连。每个客户端在连接时带有当前账号的有效服务器成员集合；Hub 对服务器事件只向同服务器成员的客户端发送。

事件统一增加 `serverId`：

```json
{
  "type": "message_created",
  "serverId": 12,
  "data": {
    "channelId": 45,
    "content": "..."
  }
}
```

规则如下：

- 频道、消息、已读、成员资料、服务器设置和语音房间事件按服务器定向发送。
- `server_added` 和 `server_removed` 按目标账号定向发送，并同步更新 Hub 的服务器订阅集合。
- 用户资料更新仅发送给与该用户存在共同服务器的连接；平台管理员未加入服务器时不接收该服务器成员的资料事件。
- 平台管理员未加入服务器时不订阅其消息、成员、在线和语音事件。
- 普通消息限流仍按账号全局计算，维持 10 秒内 8 条，避免用户跨服务器绕过限流。
- 连接队列溢出后的恢复流程先重新请求全局 Bootstrap，再重新读取当前服务器 Bootstrap。

在线状态仍表示账号至少有一个业务页面连接。Hub 维护全局账号在线租约，并为每个服务器把在线账号与有效成员关系求交集；向每个服务器成员发送该服务器自己的在线账号 ID。用户在多个服务器中在线时，可分别出现在这些服务器的在线列表中。

## LiveKit 与语音房间

LiveKit 房间名改为：

```text
guild-{guildID}-channel-{channelID}
```

LiveKit identity 继续使用 `user-{userID}`，因为账号在全平台唯一。参与者属性增加 `guild_id`、`channel_id`、有效服务器角色和令牌代次。

语音 Token 签发必须检查：

1. 当前账号是目标服务器的有效、未封禁成员。
2. 目标频道属于路径中的目标服务器，且类型为语音。
3. 当前账号未被该服务器语音禁言；禁言用户只获得订阅权限。

LiveKit Webhook、房间校准和孤儿房间清理解析新的房间名，并依据数据库中全部服务器频道校验。返回给客户端的 `voice_rooms` 事件始终带服务器 ID，且只发送给目标服务器成员。

已有“一个账号全平台只允许一个语音连接”的目标状态可以继续以 `userID` 为键维护。签发任何服务器的新频道 Token 时均使旧服务器的语音目标失效，并从旧房间移除参与者。

## 管理界面

现有管理控制台拆分为平台管理和当前服务器管理：

- 平台管理员：服务器、账号与平台邀请码。
- 所有者和服务器管理员：当前服务器频道、成员和服务器级审核。
- 所有者额外可以重命名服务器和任命/撤销服务器管理员。
- 平台管理员未加入服务器时可在平台服务器列表中创建、删除、变更所有者或加入该服务器；不能在此处看到频道和成员详情。

成员管理列表只显示当前服务器成员。服务器管理员通过完整登录名输入框添加成员，不显示平台账号浏览器。平台账号、平台邀请码和服务器生命周期操作使用独立页签，避免把平台级权限误显示为服务器权限。

## 安全与隔离要求

逻辑服务器是应用级隔离，不是密码学或基础设施级租户隔离。实现必须满足以下不可妥协的边界：

- 普通成员不能通过猜测服务器、频道、消息或成员 ID 读取、修改或删除其他服务器资源。
- WebSocket 不能把任一服务器的事件发给非成员。
- 全局 Bootstrap 不能携带普通用户未加入服务器的名称、成员、频道、在线或语音数据。
- 平台管理员未显式加入服务器时不能读取该服务器内容接口或订阅实时内容事件。
- 服务器管理员不能枚举平台账号，也不能操作其他服务器成员。
- 移出、封禁、账号停用、会话撤销和服务器删除必须立即撤销语音访问，并在可达时从 LiveKit 房间移除参与者。
- 未读、草稿、滚动位置、成员头像颜色和前端缓存都不能在服务器切换后以旧服务器数据渲染。
- 日志、审计和错误响应不得记录密码、会话明文、邀请码原码或未授权服务器内容。

## 部署与容量边界

本设计仍是单机、单 Go 进程、单 SQLite 写连接和单 LiveKit 节点。多服务器减少多套实例的运维成本，但不提高同一主机的 CPU、内存、磁盘 I/O、上行带宽或 LiveKit 媒体容量。

不同服务器仍共享：

- Go 进程故障域。
- SQLite 文件、写锁和备份恢复点。
- LiveKit 节点和 WebRTC 媒体端口。
- Caddy HTTPS/WSS 入口。

因此平台管理员应根据实际资源控制创建服务器数量和成员规模。首期不实施自动配额、限额或噪声邻居治理；这些能力在真实容量数据出现后再设计。

## 验收矩阵

最小测试用户集合：

- `platform-admin`：平台管理员，初始未加入服务器 B。
- `owner-a`：服务器 A 所有者。
- `member-a`：仅属于服务器 A。
- `member-b`：仅属于服务器 B。
- `member-ab`：同时属于服务器 A 和 B。

必须验证：

| 场景 | 预期 |
| --- | --- |
| `member-a` 登录 | 只能看到服务器 A，不能得知 B 存在 |
| `member-ab` 登录 | 看到 A、B，切换后成员和频道完全隔离 |
| 平台管理员未加入 B | 可看到 B 元数据，不能读取 B 频道、成员、消息、在线或语音状态 |
| 平台管理员加入 B | 成为 B 管理员，成员列表可见并收到 B 实时事件 |
| A 成员请求 B 的频道、消息、已读或语音 Token | 返回 404，且不泄露 B 信息 |
| A 的消息、频道或语音事件 | 不发送给仅属于 B 的客户端 |
| 所有者添加在线用户 | 目标左栏立即出现服务器，刷新后状态一致 |
| 移出当前服务器成员 | 目标停止访问、退出目标服务器语音、前端切换到可访问服务器或空状态 |
| 服务器级文字/语音禁言 | 只影响目标服务器，不影响该用户在另一服务器的聊天或语音 |
| 在 A 语音中浏览 B | A 的语音持续，面板显示 A；加入 B 语音后 A 被替换 |
| 删除服务器 | 仅删除该服务器的数据，账号、平台邀请码和其他服务器保持可用 |
| 旧数据库升级 | 全部旧用户和频道位于默认服务器，历史消息、已读和会话不丢失 |

## 后续扩展方向

本设计完成后，可在不改变平台与服务器边界的前提下逐步增加：

- 服务器内私密频道和频道成员关系。
- 服务器图标上传、昵称和频道分类。
- 经所有者控制的服务器邀请与待接受成员邀请。
- 服务器级用量统计、配额和导出。
- 用户主动创建服务器的开关和创建额度。
- 多 Go 实例、共享状态和 LiveKit 集群。

上述能力均不是本设计的前置条件；首期应优先证明服务器间的权限、实时事件和语音隔离正确。
